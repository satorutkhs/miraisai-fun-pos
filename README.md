## 使う人向け(店員・レジ係)

### 会計の流れ
1. 商品のタイルをタップ(タップするたびに+1。右下の「−」で1つ戻す)。右側に注文内容と合計が出る。
2. 「会計へ」→ お預かり金額を入れる(テンキー、または「ちょうど」「¥500」「¥1,000」「¥5,000」「¥10,000」のワンタップ)。
3. 「会計を確定する」→ お釣りと個数が出る。**伝票の番号が画面の番号と合っているか確認**し、厨房用の伝票に個数を「正」の字で記入。
4. 「次の注文へ」。

セット割引(ホットサンド2個、マキアート+ホットサンドなど)は**自動で一番安くなる組み合わせ**で計算される。割引後の合計がそのまま出るので、手計算は不要。

### 伝票(A4縦・複写想定)
- 左半分: 整理番号(お客様用)
- 右半分: 整理番号 + 注文個数(厨房用、「正」の字で記入)
- 番号は紙に印字済み。受け渡し管理はアプリではしない。

### 番号と履歴
- 画面右上の「次の伝票 No.N」が、次に使う伝票の印字番号。確定後に出る番号と手元の伝票が一致しているか確認する。
- 伝票の番号とズレたら「売上・履歴 → 次の番号を変更」で合わせる。
- 間違えて会計したら「売上・履歴 → 取消」(番号は欠番として履歴に残り、売上から除かれる)。
- 「CSV保存」でこまめにバックアップ(端末のダウンロードフォルダに保存)。表計算ソフトで開ける。
- **ブラウザのサイトデータ(閲覧履歴の「データを消去」)は消さないこと**。履歴が全部消える。

### ラストセール(最終日の売り切り用)
画面右上の「ラストセール OFF / ON」で価格表を切り替える。確認ダイアログで OK するとその場で切り替わる(オフラインでOK、端末に保存される)。

- ON の間は画面が赤枠になり、ヘッダー下の帯に「何がいくらになったか」が出る。
- 切り替え前に会計した注文の金額は変わらない。履歴・CSVの `sale` 列が 1 ならラストセール価格での会計。
- 元に戻すときは同じボタン。
- 2026年の設定値は下の[商品・料金](#商品料金)を参照。

## 商品・料金

2026年の設定(この表が正。コードの価格表は `src/pricing.ts`)。

| 内容 | 通常 | ラストセール |
|---|---|---|
| ミルクマキアート | 300円 | 300円 |
| エスプレッソマキアート | 300円 | 300円 |
| ホットサンドハーフ(キャベツ抜きも同価格) | 300円 | 300円 |
| ホットサンドハーフ2個 | 500円 | 400円 |
| マキアート+ホットサンドハーフ | 500円 | 400円 |
| マキアート+ホットサンドハーフ2個 | 700円 | 600円 |
| アイスコーヒー | 200円 | 200円 |
| ホットコーヒー | 販売なし | 200円 |

- マキアートは2種(ミルク/エスプレッソ)、ホットサンドは通常/キャベツ抜きの2種。**種類が違っても同価格で、セット割引は種類をまたいで共通**(例: エスプレッソ+キャベツ抜き=500円)。
- コーヒー(アイス/ホット)はセット割引の対象外。
- 割引は「セットの組み合わせを総当たりして一番安くなる組み合わせ」を自動採用(`calcPrice` in `src/pricing.ts`)。
- ホットコーヒーはラストセール ON の間だけタイルが出る。OFF に戻すと入力中の分も消え、通常価格での会計はシステム側でも拒否される。

## タブレットの準備

想定: Android タブレット1台(Chrome)。**前日までに、Wi‑Fiのある場所で**やる。

### 初回
1. タブレットのChromeで公開URL(https://satorutkhs.github.io/miraisai-fun-pos/)を開く。
2. 画面が出たら10秒ほど待つ(この間にオフライン用のキャッシュが作られる)。
3. Chromeメニュー(︙)→「ホーム画面に追加」または「アプリをインストール」。
4. ホーム画面のアイコンから起動する(全画面・横向き)。一度閉じてもう一度開く。
5. **機内モードにして**アイコンから起動し、注文→会計→お釣り→売上・履歴→CSV保存まで通しで試す。
6. 試した注文は「売上・履歴 → 取消」で消す。「次の番号を変更」で、伝票の最初の番号に合わせる。

### アプリを更新したあと(価格変更・不具合修正など)
1. タブレットをオンラインにする。
2. ホーム画面のアイコンから開き、10〜20秒待つ。
3. アプリを完全に閉じて(最近のアプリ一覧から消す)、もう一度開く。
4. 変更が出ているか確認(右上のボタン、価格、タイルなど)。
5. 機内モードに戻しても、そのまま使える。

履歴・次の番号・ラストセールの状態は更新後も残る。

### 当日の注意
- 画面スリープは自動で抑える作りだが、念のため端末の画面オフ時間を長くするか、充電しながら使う。
- 終了後は「CSV保存」で売上を保存する。

## 来年度に向けて変えるところ

**原則: 価格や商品を変えたら、コード・テスト・このREADMEの料金表を揃えて更新する**(ルールは [CLAUDE.md](CLAUDE.md))。

### 価格だけ変える
1. `src/pricing.ts` の `REGULAR`(通常)と `LAST_SALE`(ラストセール)を編集する。
   - `unit`: マキアート/ホットサンドの単品、`hs2`: ホットサンド2個、`mh`: マキアート+ホットサンド、`mhh`: マキアート+ホットサンド2個、`coffee`: コーヒー。
2. `src/pricing.test.ts` の期待値を新しい価格に合わせて直す(**先にテストを直してから**実装するとミスに気づきやすい)。
3. このREADMEの料金表と、HANDOFF.md の該当箇所を更新する。
4. 画面の価格表示・ヘッダー下の帯・ラストセール切替の確認ダイアログは、価格表から自動で作られるので直さなくてよい。

### 商品を増やす・減らす
商品ごとの個数は「注文」「集計」「履歴」「CSV」に出てくるので、次の場所を揃えて直す。過去の例は `git log` で「Add iced/hot coffee」「Add milk/espresso macchiato and no-cabbage hot sand」を見ると、変更の範囲が分かる。

1. `src/pricing.ts`: `Counts` 型、`emptyCounts`、`calcPrice`(セット割引の対象にするかどうか)。
2. `src/store.ts`: `Order` / `Summary` 型、`checkout`、`summary`、CSVのヘッダーと行、**旧データを読み込むときの既定値**(`load` の中)。
3. `src/main.ts`: `PRODUCTS`(タイルの定義。`kind` は `'unit'` か `'coffee'` で、どの価格を使うか)、`loadDraft`、履歴画面の表と集計のカード。
4. `public/img/` に画像を入れる(幅900px程度のJPEG、1枚100KB前後。外部URLは使わない)。
5. テスト(`pricing.test.ts` / `store.test.ts`)を先に書く。
6. `npm run check` と `npm run build`、そして**実際に画面を見て**確認する(CSSの崩れはテストでは分からない)。

### 保存データの互換性
- 端末内の保存キー(`pos.*`)の名前を変えると、前に保存した履歴が読めなくなる。変えるなら移行処理を書く。
- 注文のデータ項目を増やすときは、`store.ts` の `load` で「古い注文には既定値を入れる」処理を忘れない(既存のテストが例になる)。

## 開発

必要なもの: Node.js 22(`.nvmrc` あり)、Git。

```bash
git clone https://github.com/satorutkhs/miraisai-fun-pos.git
cd miraisai-fun-pos
nvm use              # Node 22。なければ nvm install
npm ci               # 依存のインストール
npm run dev          # 開発サーバ(同一Wi-Fiのタブレットからも http://<PCのIP>:5173 で確認可)
npm run check        # 型チェック + テスト(コミット前に必ず)
npm run build        # dist/ を生成(PWAも含む)
npm run preview      # ビルド結果の確認(Service Workerはこちらでしか確認できない)
```

### 作業の進め方(ルール)
- **`main` に直接pushしない。** `feat/…` `fix/…` `chore/…` のブランチを切り、PRでマージする。`main` へのマージで本番に自動デプロイされる。
- **ロジック(`src/pricing.ts` `src/store.ts` `src/cash.ts`)はテストを先に書く**(TDD)。UIは `src/main.ts` と `src/style.css`。
- コミット前に `npm run check` と `npm run build` を通す。
- **ネットワークに依存する機能(外部API・CDN・Webフォント)を入れない。** 会場はオフライン。
- PRは**常に `main` 宛ての単独PR**にする(別PRの上に積まない。過去にマージ漏れが起きた)。

```bash
git switch main && git pull
git switch -c feat/○○          # fix/ chore/ も可
# テストを先に書く → 実装 → npm run check && npm run build
git push -u origin feat/○○
# GitHubでPRを作成 → CI(npm run check + build)が通ったら main にマージ
```

## 本番へのデプロイ・リリース

### デプロイ
`main` にマージすると GitHub Actions(`.github/workflows/deploy.yml`)がテスト→ビルド→GitHub Pages へ公開する。進み具合は GitHub の「Actions」タブで確認(1分ほど)。

初めてこのリポジトリで Pages を使うとき(または別アカウントに移したとき)は、リポジトリの **Settings → Pages → Source を「GitHub Actions」** にする。これを忘れると404になる。

### リリース(バージョンの記録)
大きな変更をまとめて `main` に入れたら、GitHub Release を作ってバージョンを残す(`v1.2.0` のような番号)。本文には**公開URL・変更点・料金表・更新方法**を書く。

```bash
gh release create v1.3.0 --target main --title "v1.3.0" --notes-file notes.md
```

### 別アカウント・別リポジトリに移すとき
- 公開URLは `https://<ユーザー名>.github.io/<リポジトリ名>/` になるので、README・HANDOFF・リリース本文のURLを直す。
- URLが変わると、タブレットでは**新しいURLで最初から「ホーム画面に追加」し直す**必要がある(履歴も別になる)。
- `vite.config.ts` の `base: './'` は相対パスなので、リポジトリ名が変わっても直さなくてよい。

## 構成とデータ

- Vite + TypeScript(strict)+ Vitest。UIはフレームワークなしの素のTypeScript(`src/main.ts`)。PWAは `vite-plugin-pwa`(`vite.config.ts`)。
- ファイル:

| ファイル | 役割 |
|---|---|
| `src/pricing.ts` | 価格表(`REGULAR` / `LAST_SALE`)、セット割引の最安計算、商品の個数の型 |
| `src/store.ts` | 会計・履歴・番号・ラストセール状態・CSV(localStorage) |
| `src/cash.ts` | テンキー入力、お預かりのクイック金額 |
| `src/main.ts` / `src/style.css` | 画面(注文/支払い/完了/履歴) |
| `*.test.ts` | 上3つのテスト |
| `public/img/` | 商品画像(オフライン用にPWAへ同梱) |

- データ保存先は端末の localStorage のみ。キーは次のとおり。

| キー | 中身 |
|---|---|
| `pos.orders.v1` | 会計済みの注文(履歴) |
| `pos.next.v1` | 次の伝票番号 |
| `pos.draft.v1` | 入力途中の注文 |
| `pos.sale.v1` | ラストセールの ON/OFF |

- CSVの列: `no,time,milk,espresso,hotsand,hotsandnc,icecoffee,hotcoffee,total,discount,received,change,voided,sale`

## 困ったとき

| 症状 | 対処 |
|---|---|
| 更新したのに古い画面のまま | オンラインでアプリを開いて10〜20秒待ち、完全に閉じて開き直す。それでもダメなら**CSVを保存してから**、Chromeのサイト設定でこのサイトのデータを消し、ホーム画面に追加し直す(履歴は消える) |
| 商品やタイルが出ない・画像が出ない | 上の「古い画面のまま」と同じ。古いキャッシュが残っている |
| 会計後の伝票番号が紙とずれた | 「売上・履歴 → 次の番号を変更」で合わせる |
| 間違えて会計した | 「売上・履歴 → 取消」 |
| 履歴を最初からにしたい(本番前のリセット) | 試した注文を全部「取消」して「次の番号を変更」。完全に消すなら、CSVを保存してからサイトデータを消す |
| 画面が真っ白 | ページを再読み込み。直らなければ別のタブレット/PCで公開URLを開いて症状を確認し、開発者に連絡 |
| Pagesが404 | Settings → Pages → Source が「GitHub Actions」か確認し、Actionsタブでデプロイが成功しているか見る |
